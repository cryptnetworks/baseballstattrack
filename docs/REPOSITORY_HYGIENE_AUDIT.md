# Repository hygiene audit

## Scope and baseline

This audit began from clean `main` at
`9ed6a1df553fb033a18a6e1e9106713a4684ac86`. The starting tree contained 641
tracked files: 243 application files under `src/`, 166 tests, 111 documentation
files, 27 Prisma files, 23 scripts, 21 Discord-service files, 17 GitHub files,
and the remaining runtime and repository configuration.

The review covered tracked-file size and type, ignored/generated output, static
and dynamic entrypoints, TypeScript imports, Next.js routes, Python package
imports, package scripts, GitHub Actions, Docker and Compose references,
documentation links, assets, fixtures, dependencies, file modes, duplicate
content, and history for removal candidates. The pre-cleanup baseline passed the
Node and Discord test suites.

## Generated and local output

The working copy contains ignored local output such as `.next/`, `node_modules/`,
Python virtual environments and caches, `tsconfig.tsbuildinfo`, `.DS_Store`, and
local environment files. None is tracked, included in Docker build contexts, or
eligible for repository deletion. Existing ignore rules cover these artifacts.

No tracked duplicate file content, editor backup, log, database, coverage,
temporary export, build directory, or broken symbolic link was found.

## Deferred cleanup

- Documentation consolidation is deferred. Similar subject matter often serves
  different audiences (contract, operator procedure, ADR, or historical audit),
  and removing it without product-owner review risks losing required context.
  Documentation maintainers and the relevant product owner should review any
  future consolidation.
- The Python authoring lock and exported hash-pinned locks intentionally overlap.
  Replacing them with one format requires a CI/container packaging decision, not
  a file cleanup. The Discord service and release maintainers own that decision.
- Domain modules whose current consumers are tests are retained as explicit,
  tested contracts. Removing or folding them would be an architecture/API change
  for the domain and API maintainers to review.

## Validation

The cleaned tree passed:

- the full `npm run verify` gate, including formatting, lint, type checking, 881
  tests, repository policy, security workflow checks, documentation publication,
  the statistics API contract, Prisma schema validation, the production build,
  experience and PWA budgets, and the production dependency audit;
- the Discord service Ruff and pytest checks (14 tests);
- documentation workflow validation and Compose configuration validation;
- all 25 migrations against a disposable PostgreSQL 17 database, followed by
  migration status, constraint and trigger verification, and relational
  representability checks;
- the production container smoke suite, including runtime, migration, and Discord
  image builds, clean migration deployment, restart persistence, volume reset,
  readiness, non-root execution, failure behavior, and secret-disclosure checks;
- a post-cleanup reachability scan covering all 241 executable TypeScript and
  JavaScript files under `src/`, with no unreachable source remaining.

## Safety review

- **New engineer:** repository entrypoints, instructions, and operational guides
  remain intact; the stale agent lock no longer suggests unavailable tooling.
- **Release engineer:** Dockerfiles, Compose definitions, release workflows,
  environment templates, production scripts, and rollback procedures are
  unchanged.
- **Security engineer:** authentication and authorization controls, tests,
  CodeQL, dependency/container/secret scans, privacy guidance, and audit scripts
  are unchanged.
- **Database engineer:** every Prisma migration, schema file, migration test,
  backup fixture, restore procedure, and representability check is unchanged.
- **Maintainer:** ADRs, milestone audits, correction history, provider contracts,
  and API contracts remain available and linked.

The cleanup removes no runtime entrypoint, route, export in use, dependency,
deployment input, test, security control, database artifact, or published
documentation source.
